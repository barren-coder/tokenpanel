Token Plan 额度托盘应用 · 技术方案

Windows 常驻托盘小应用 · 规划于 2026-10-28 · 所有数据源均已在本机实测
当前状态 · v2 已可日常使用

配置页和美化托盘都做完了，仍然零安装。不用装 Rust、不用装 Node，一条命令就跑起来。

首次运行自动探测 Key：从 .codex/auth.json、.claude/settings.json、环境变量里逐个试，通了就自动存进配置（DPAPI 加密，绑定当前用户）。

配置页支持 6 家供应商切换、自定义 API 地址与 Key、刷新间隔、告急阈值、三种图标样式实时预览。

02凭据从哪来：不用重新录入

你本机 CC Switch 的数据库里已经有全部供应商配置，这是最容易忽略的一笔现成资产。

~/.cc-switch/cc-switch.db      # SQLite
  └─ providers 表
       ├─ app_type            claude / codex / gemini / hermes / opencode ...
       ├─ settings_config     JSON，内含 base_url 与 API Key
       ├─ meta.usage_script   JSON，含 codingPlanProvider（如 "minimax"）
       └─ is_current          是否当前启用

实测你当前的配置：[codex] MiniMax-2421 处于启用状态，配额模板为 token_plan / minimax，刷新间隔 5 分钟。

但要小心：同一个订阅的两处 key 有效性可能不一致。实测 .claude/settings.json 里那把 MiniMax key 调用额度接口返回 1004 cookie is missing（无效），而 .codex/auth.json 里那把正常。所以凭据发现必须做多源探测 + 可用性验证，不能只读第一个找到的。

建议的凭据发现优先级：

1. 应用自己的配置（%APPDATA%\QuotaTray\config.json）   ← 用户显式指定，最高优先
2. CC Switch 数据库（cc-switch.db → providers）         ← 零配置自动发现
3. 原生 CLI 凭据（.codex/auth.json、.claude/.credentials.json）
4. 环境变量（MINIMAX_API_KEY 等）

03技术选型

本机现状决定了成本：Node 22 ✅ WebView2 134 ✅ Rust ✗ .NET SDK ✗ Python 无 tkinter ✗

Tauri v2 推荐5–10 MB40–60 MB 原生托盘 ✅ / 透明无边框窗口 ✅需装 Rust（一次性） 正式版首选
Electron80–150 MB150–250 MB ✅ / ✅ 最灵活✅ Node 现成 要开发速度、能接受体积就选它
.NET 8 WPF~15 MB40 MB ✅ / ✅需装 SDK 只跑 Windows 的话很稳，但 UI 迭代慢
Python + pystray~40 MB60 MB ✅ / 弱缺库且无 tkinter 不推荐：打包臃肿、外观受限

为什么推荐 Tauri v2

一个「看一个数字」的常驻小工具，最不该付出的代价就是 200 MB 内存和 150 MB 安装包。Tauri 复用你系统里已装的 WebView2，二进制只有几 MB；托盘图标、无边框透明窗口、开机自启都是一等公民 API；而且它和 CC Switch 同栈，将来想直接读它的 SQLite 或做联动，几乎没有摩擦。

唯一成本是装一次 Rust 工具链（约 1.5 GB、10–15 分钟），之后编译 1–3 分钟。如果这一步让你卡住，就用 PowerShell 原型顶着，功能完全一样。

统一数据模型

type TierName = 'five_hour' | 'weekly' | 'monthly';

interface QuotaTier {
  name: TierName;
  remainingPercent: number;      // 统一为「剩余」，内部换算
  resetsAt: string | null;       // ISO8601
  status: 'ok' | 'exhausted' | 'absent';
}

interface QuotaSnapshot {
  providerId: string;            // 'minimax' | 'kimi' | 'claude' | ...
  planName: string | null;
  tiers: QuotaTier[];
  fetchedAt: string;
  error: { kind: 'auth' | 'network' | 'parse'; message: string } | null;
}
设计要点：Adapter 只负责「把各家奇形怪状的响应变成 QuotaTier[]」。UI 层永远只认 QuotaTier，加新供应商时不用碰任何界面代码。这是这个项目唯一值得认真设计的抽象。

05界面规格

托盘图标

32×32 实心圆盘 + 白色数字。≥50% 青 / 20–50% 琥珀 / <20% 红。数字本身就是百分比，不再画环形（16px 下环形会糊）
交互
  • 悬停 → tooltip「5h 67% · 周 67%」
  • 左键 → 弹出详情面板（两条进度条 + 重置倒计时）
  • 右键 → 立即刷新 / 切换供应商 / 开机自启 / 退出
托盘图标的真实约束：Windows 托盘只有 16×16 逻辑像素（125% 缩放时 20×20）。三位数「100」勉强能塞，再长就必须降字号或缩写。这也是为什么图标上只放一个数字 —— 想放两个窗口的百分比，一定会糊成一团，第二窗口的信息留给 tooltip 和面板。

07踩过的坑（都会踩）

坑现象处理
系统代理 请求直接超时，看起来像接口挂了 本机有 http_proxy=127.0.0.1:2537。curl 加 --noproxy '*'；Rust reqwest 显式 .no_proxy()；Python ProxyHandler({})
国际站不通用 api.minimax.io 返回 1004 cookie is missing 国内账号只能用 api.minimaxi.com，别自动 fallback 到 .io
video 档位 返回 100% 剩余，会让界面误以为额度充足 status=3 表示「无此限额」，必须过滤掉
百分比在动 实测 2 分钟内 72% → 67% 这是真实消耗（你正在跑 Codex）。刷新间隔别低于 3 分钟，否则看着像抖动
非官方接口 Claude 的 /api/oauth/usage 历史上多次 429 必须有缓存兜底：查询失败时显示上次值 + 灰化，不要清零
CC Switch 升级 cc-switch.db 的 schema 会变 读库要 try/catch 降级到原生凭据，绝不因读库失败而整体不可用
凭据明文 本地配置存 API Key 用 Windows DPAPI（CryptProtectData）加密，绑定当前用户

v2 开发中踩到的三个坑（都已修）

坑现象根因与修法
变量名大小写 所有输入框、下拉框都是白底，深色主题失效 PowerShell 变量名不区分大小写，主题表 $T 和函数里的 $t（TextBox）是同一个变量，一创建控件主题就被覆盖 → C $T.Field 取到空值。改名为 $Theme
受限 HTTP 头 请求直接抛 ArgumentException Content-Type / Accept / User-Agent 是 .NET 的受限头，不能写进 Headers 集合，必须用 ContentType 等属性
截图不可信 截图里控件是白底，实际运行却是深色（或反之） DrawToBitmap 对原生控件（TextBox/ComboBox）渲染不准，必须用 CopyFromScreen 截真实屏幕；且要注意 DPI 缩放会让坐标偏 1.25 倍
还有一个 UI 细节值得记：并排的两列 Label，如果左边那个宽度过大，会因为矩形背景盖住右边 Label 的首字（表现为「认证方式」显示成「证方式」）。排两列时左列宽度必须小于右列的起始 X。
