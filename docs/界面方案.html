推荐方案 A 的可读性细节

  • 字号 9px 是底线 —— 中文小于 9px（96 DPI）会糊，125% 缩放时 9px 约等于 11 物理像素，刚好清晰。
  • 字重用 Regular，不要 Bold —— 小字号下 Bold 会让笔画粘连，反而更难读。这一点和直觉相反。
  • 颜色用 #9AA5B5 而非纯白 —— 纯白在小字号下会「发胖」产生光晕，中性灰更锐利，也不会和圈里的白色数字抢注意力。
  • 智能缩写 —— 不靠截断，而是配置时就存一个短名：MiniMax Coding Plan → MiniMax，Kimi For Coding → Kimi。截断（"MiniMa…"）比缩写丑得多。
  • 标签与圆圈间距 5px —— 太近会视觉粘连，太远会让圆圈和文字失去从属关系。
  • 卡片背景不透明度 ≥ 97% —— 半透明背景叠在复杂壁纸上，小字立刻不可读。这是必须放弃「玻璃拟态」的地方。
一个反直觉但重要的取舍：不要做真透明背景。 你可能想要那种 macOS 风格的毛玻璃悬浮窗，但小字号中文叠在半透明背景上，遇到花哨壁纸会完全糊掉。折中做法是卡片接近不透明（97%），只在边缘做轻微阴影——看起来仍然是「浮在桌面上」，但文字始终清晰。

03交互设计

动作行为实现要点
按住拖动整个卡片任意位置可拖，位置实时跟手记录按下点与窗口偏移；松手时把坐标存进配置
单击折叠 ↔ 展开切换移动距离 < 4px 才算点击，否则算拖动。这个阈值很关键，不然拖动完会误触发展开
位置记忆下次启动回到上次位置存相对屏幕右下角的偏移，换分辨率不会跑到屏幕外
贴边吸附拖到屏幕边缘 20px 内自动吸附可选。加了更像「电脑管家」，但会让自由拖拽手感变差
不抢焦点点击卡片时不夺走当前窗口的输入焦点需要 Win32 WS_EX_NOACTIVATE，否则你在编辑器里打字，点一下卡片光标就跳走了
右键菜单刷新 / 设置 / 隐藏 / 退出复用现有托盘菜单逻辑

04排序规则

你说「显示排最前的 3 个」，这个「排最前」得有明确规则。三个候选：

规则效果评价
按剩余百分比升序最紧张的排最前（12% → 45% → 67%）推荐。你一眼看到的就是最该关注的
按添加顺序你加的顺序，稳定不变可预测，但可能把 90% 的排前面，浪费位置
按消耗速度降序掉得最快的排最前更智能，但需要历史采样，属于 L2

建议：默认按剩余升序，设置页给一个下拉可切「添加顺序」。同时圆圈颜色本身也编码了状态，即使排序不理想也不会误判。

05技术实现：这次要不要换技术栈

关键变化：悬浮窗 + 圆圈 + 中文小字 + 展开动画，这四件事把 WinForms 逼到了墙角。

我的判断：这次该迁 Tauri 了。

上一轮我建议「先别迁」，因为需求只是托盘一个数字，WinForms 够用。但你现在要的是悬浮窗 + 圆圈 + 小字 + 动画——这四项恰好全是 WinForms 的短板，而全是 Web 技术的基本功。硬用 GDI+ 自绘，你能得到 70 分的版本，但要付出比 Tauri 更多的时间去调锯齿和动画。

唯一代价是装一次 Rust（约 15 分钟）。考虑到这个工具你打算长期挂着，值得。

迁移后架构不变，只换渲染层

  • 数据层原样保留 —— Invoke-Provider、6 个 Parse-*、DPAPI 加解密、自动探测 Key，全部可以照搬逻辑到 Rust 或 JS。
  • 配置格式不变 —— %APPDATA%\QuotaTray\config.json 继续用，只是 providers 从单条改成多条。
  • 渲染层重写 —— 上面这套视觉稿本身就是可直接用的 HTML/CSS，Tauri 里就是它。
  • 托盘保留 —— 悬浮窗和托盘可以共存，托盘图标仍显示最紧张的那个。
